# Git-хуки безопасности

Защита от повторения инцидента с утечкой дампов БД (30.06.2026): дампы попали в
**публичный** репозиторий через `git add -f` (в обход `.gitignore`).

- **pre-commit** — (1) блокирует коммит дампов БД (`*.sql`, `*.sql.gz`, `*.dump`),
  файлов `backup-*` и секретов (`.env`, `.env.*`; кроме `.env.example`) даже на
  `git add -f`; (2) гоняет **статанализ** изменённого кода (`scripts/check.sh --staged`).
- **pre-push** — последний барьер: сканирует **всю** отправляемую историю, ловит
  файл, даже если он был добавлен и удалён внутри тех же коммитов.

## Статанализ (проверка любых изменений)

`scripts/check.sh` — типы+линт кабинета (`tsc -b` + `eslint`) и синтаксис бэкенда
(`py_compile`). Запускается автоматически в pre-commit по изменённым файлам; коммит
с ошибками типов/линта блокируется (варнинги не блокируют).

```bash
scripts/check.sh            # весь проект (кабинет + бэкенд)
scripts/check.sh --staged   # быстро: только staged-файлы (так зовёт pre-commit)
cd cabinet && npm run check  # то же для кабинета (tsc + eslint)
```

Разово выключить: `SKIP_CHECKS=1 git commit …` или `git commit --no-verify`.

## Активация (нужно один раз на каждый клон)

```bash
git config core.hooksPath scripts/git-hooks
```

Обход в исключительном случае: `git commit --no-verify` / `git push --no-verify`
(крайне не рекомендуется — именно так и утекают данные).
